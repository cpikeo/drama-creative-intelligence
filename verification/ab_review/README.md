# A/B 双人盲评：两套固定任务

## 任务一：T-AB1（v7.1.0 vs v7.2.0）

目的：回答一个具体问题——**v7.2.0 为补齐摄影 / 美术 / 表演层次 / 视效 / 声场 / 视觉主张能力而增加的 +3.6% Context，是否买到了更好的产出质量？**

## 任务二：T-AB2（v7.2.1 vs v7.3.0，视觉连续性与角色一致性）

目的：回答一个具体问题——**v7.3.0 的跨镜接缝规则（入点 / 出点、越轴声明、跨场依据、
跨镜身份与空间漂移的责任层）是否买到了更可信的连续画面与角色一致性？**

固定任务与七个场景（连续动作、多镜头对话、转身与移动、同角色不同景别与光线、
跨场景转换、图生视频、角色状态变化）见 [task_continuity.md](task_continuity.md)。

## 版本锚点

- `skill-v7.2.1` → 连续性优化前的 HEAD（本仓库可复现）
- `skill-v7.3.0` → 连续性优化后的提交（本仓库可复现）

**诚实记录**：`skill-v7.1.0`（d3567cb）与 `skill-v7.2.0`（483a153）两个标签在
CHANGELOG v7.2.1 中有记录，但**这两个提交与标签不存在于本仓库的 git 历史中**
（`git cat-file` 报 not a valid object name）。因此 T-AB1 的版本对照**在本仓库内不可复现**，
其历史结论只能作为作者自述，不作为已验证能力；要恢复它，必须从作者原始历史导入这两个提交。
T-AB2（v7.2.1 vs v7.3.0）的两个锚点在本仓库内均可用，可复现。

## 运行

```bash
bash verification/ab_review/run_ab.sh                              # T-AB1
bash verification/ab_review/run_ab.sh skill-v7.2.1 skill-v7.3.0    # T-AB2
```

输出两个版本的文件指纹与度量，并在 `snapshots/` 导出可交付给评审员的技能快照。

## 诚实边界（不可伪造的部分）

- **双人盲评本身必须由两名独立人类评审完成**；本环境没有第二位评审，不得由同一作者扮演两名评审、不得用关键词命中率替代。
- 本环境**没有媒体生成工具**，因此 T-AB1 只覆盖创作与规格层（SPEC QA）；T-AB2 的七个场景中，
  媒体层（真实关键帧、视频、成片）同样只能在有工具的环境执行；没有工具的运行，
  MEDIA QA / CUT QA 一律 PROVISIONAL，不参与对比。
- 主持人不参与评分；评审员在解盲前不得知道 A/B 对应关系。
- 结论必须公开九维度的分维度分数，不得只给加权总分（见 [../rubric.md](../rubric.md) §3）。
- 成本账逐版本记录（token / 生成次数 / 返工 / 媒体成本 / 观看时长）；缺项写"未测量"，不得填 0。

## 与成本回收的联动
