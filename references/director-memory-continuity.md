# 导演记忆、World State、Continuity Graph、生产与创意 QA

这一份协议是 Director Core 持续记忆模型的操作层，取代分散的角色表、资产表、连续性表、阶段摘要、任务缓存和 Agent 交接。六种真相的定义、Character DNA 与变化规则、因果链、图谱节点与边词汇、QA 三层与生产门均已固定于 SKILL，本文件不重新定义它们，只固定**怎么存、怎么读、怎么传播、怎么生产、怎么验收**。事实只写一次；Context 只加载解决当前决定所需的节点与历史。

## 1. 三层项目真相

```text
<项目>/
├── 创作总控.md               # Director Memory：Bibles、Canon、Graph、全剧 Intent、分集 Snapshot
├── 剧集/EP001.md              # 本集事实：剧本、状态表、分镜、声画规格、生产追踪、剪辑、QA
└── 制作/EP001/                # 真实参考、任务预览、生成媒体、导出和运行观察；不冒充 Canon
```

小项目可只保留总控加一集文件；不预建空集，不按岗位拆文件。`创作总控.md` 是 Memory，不是把全剧内容复制进去的百科；只保存下游会依赖的可追溯事实与未决线索。

| 记忆域 | 权威内容 | 不能放进这里 |
|---|---|---|
| **World Bible** | 时代、地点、势力、规则、资源、环境、空间可见事实 | 当前单镜姿态或无依据推测 |
| **Character Bible** | Character DNA（含 Voice DNA）、稳定身份、关系基线、弧线历史 | 每集重复情绪描写 |
| **Visual Bible** | 媒介、时代锚点、视觉方向、象征系统、色板基线、资产身份、连续性锁（含配音参数锚点） | 单镜瞬态或生成文件路径 |
| **Narrative Canon** | 已确认事实、时间线、来源定位、信息权限、改编边界 | 临时想法与未验证假设 |
| **Events / History** | 已发生事件、因果（逐词填写因果链）、不可逆后果 | 尚未发生的剧情 |
| **Relationships** | 双方立场、知识、债务、承诺、权力与变化历史 | 没有证据的“人物设定” |
| **Foreshadowing / Promise** | 建立位置、观众权限、预期回收条件、当前状态（生命周期见 SKILL §02） | 已忘记的装饰细节 |
| **Assets** | 人/地/物身份、变体、状态、参考范围、权利信息 | 逐镜动作脚本 |
| **Directorial Intent** | 创意发动机五要素（主题/矛盾/戏剧前提/独特机制/情绪论点）、观看承诺、情绪、节奏、信息释放、视听策略、禁区/例外 | 冒充已发生的故事事实 |

### 角色分层记录

- **A 级**：完整六层 DNA 卡 + 全部 LOCK（含配音参数锚点）+ 定妆参考图；
- **B 级**：仅四字段——Identity 锚点 / Visual 锚点（一图一描述）/ Voice 锚点（音色 ID + 一句音色）/ 一句话 Psychology 与关系定位；不建完整弧线，不建 PROMISE；
- **C 级**：不建持久 ID、不进总控；跨集出场或获得 PROMISE 时升 B 级。层级变化记 `DEC-L`，写在剧集文件。

### 系列承诺账

契约期记录：系列级 PROMISE（主题/关系/物件/观众期待）| 埋设位置 | 计划回收集数 | 当前状态。两条定律：

- **出去压力 → 进入压力**：EP n 的出去压力必须成为 EP n+1 Snapshot 前因的输入；接不上即断集。
- **回收漂移**：计划回收集数必须改动时记 `DEC-H` 并写明原因；禁止静默跳过或永久不回收（除非显式 `Abandoned`）。

## 2. Evidence Boundary 与决定记录

**Evidence 记录**：`ID / Type / Source / Confidence / Usable for`。Type 仅为 `USER / CANON / HISTORY / MEDIA / QA / HYPOTHESIS`；Source 定位到创作者指令、文件、镜头或时间码；Confidence 为 `Confirmed / Observed / Inferred / Unverified`；并写明它能支持什么、不能支持什么。

**决定记录**：`DEC-L`/`DEC-H` 的判定标准固定于 SKILL §02。每条 `DEC-H` 按 `Evidence → Context → Trade-off → Decision → Consequence → Verification` 链填写：`Trade-off` 只列真实可行且后果不同的方向；`Verification` 指向具体场、镜、媒体或后续 Snapshot；未来压力按 Causal Memory 标准填写（具体的下一集压力，非“长期影响”）。

**因果条目**：存入 Events/History，逐词填写因果链（SKILL §02）；每条必须能反查到其 State Delta 与下游 Pressure，并回答“它新增了什么约束”。

**视点时间**：EVENT 与场景记录带视点时间（场景讲述的故事时刻）及其与当前的关系（现在/闪回/梦境/想象/未来）。闪回、梦境、想象是视点，**不写 State**；其中揭示的信息进入相关角色的 `knows` 边与相关 PROMISE，不是世界事实（除非剧情已建立该事件本身已发生）。

**媒体证据规则**：生成文件和模型输出可作为 `MEDIA` 或 `QA` Evidence，但永不自动晋升 Canon/State；其可见细节只证明该文件中可见。晋升为新世界事实必须完成 `真实媒体检查 → MEDIA QA → DEC-H → Canon/State`；模型补全、单镜可见与技术成功都不能越过此门。

**冲突流程**：既定事实冲突时，先检查类型和来源，再判定是状态变化、信息误导、主观画面、创作者 retcon 还是错误；不以新 prompt 覆盖旧记录。任何记录应能回答：谁/什么、在哪/何时、为什么成立、从何而来、与谁有关、何时生效、何时终止、影响什么。

## 3. World State 与 State Snapshot

**World State**（节点列表见 SKILL §03）：每个节点只留会影响行动、风险、信息、画面、声音或后续因果的字段。空间区分三档：**可见事实 / 有依据推测 / 未知区域**；未知背面、精确尺度、隐藏门或产品细节不得为镜头方便虚构。

**每集 Snapshot**：每集开头读入、结尾写出同一张状态卡：

```text
EP### State Snapshot
前因：上集及更早仍在生效的事件/承诺
当前状态：世界、角色、关系、资产、时间/环境、观众知识
本集变化：谁因何事从什么变到什么
后果：已落地、不可逆或将限制下一行动的结果
未决线索：PROMISE、风险、误解、资源/信息缺口及预期责任
```

此卡是下一集的直接入口，不是剧情摘要。新集先继承它，再推演本集；结尾同时保留最小 `Snapshot Diff`：只列新增/改变/移除的节点、边和 Promise 状态，避免复制整张状态卡。若新剧本违背 Snapshot，必须写出事件、回忆、蒙太奇、时间跳跃或 retcon 的桥，而不是默默覆盖。

### 每集状态表

每集文件维护一张时间/地点/光态表，是关键帧与视频规格的单一源：

```text
| SC/SH | 故事时间 | 距上场 | LOC | 光态（光源/时段/天气/色温） | 备注 |
```

光态变化是 STATE 变化（走变化规则）；闪回场的时间是视点时间，不影响当前光态。关键帧、视频与声音规格按行引用本表，不另写自由文本光态。

## 4. Continuity Graph 操作

节点类型与边词汇见 SKILL §03。操作规则：

- **节点 ID**：`CHAR-`、`LOC-`、`PROP-`、`EVENT-`、`REL-`、`PROM-`、`ASSET-`、`SC-`、`SH-`、`MEDIA-` 与十类节点一一对应。操作型 ID 不进图谱：`VAR-`（状态变量）、`LOCK-`（连续性锁：角色造型、配音参数、空间结构、色板）、`GEN-`（生成规格）、`CUT-`（剪辑段）、`P-`（presentation 页面）。ID 表示同一实体、事件或叙事职责而非行号；润色/小改 prompt 不换 ID；真正拆并实体、事件或镜头才记录替代关系。
- **边模式**：每条边带来源、前后状态与生效范围，必要时带观众是否已知。空间/可见性/依赖是边的受控属性，不另造平行关系词。
- **反查**：面对一个决定，应能反查它会 `changes` 什么、`limits`/`enables` 谁、压迫或回收哪个 Promise。
- **随剧本写入**：每集剧本定稿后同步产出图谱增量，每条新增/变更边一行：
  `EDGE-ID: from — 动词 → to | 来源（场景/台词）| 前后状态 | 生效范围 | 观众已知?`
  无增量，剧本不算定稿（SPEC QA 检查项）。
- **写场前反查**：写一场戏前查并引用 ① 目标角色 `knows/believes`（行为是否超出其知识）；② `holds/owes`（筹码是否成立）；③ 相关 PROMISE（本场是否推动或回收）；④ 相关 LOC/PROP 当前 State；结论写进镜头规格“连续性依据”栏。查不到答案先补记忆，再写场。
- **状态传播**：同一变化规则（SKILL §03）适用于道具、地点、天气、光态、画内文字与声音。相邻镜检查，也检查远距离因果：早期交出的物件、获得的知识、留下的伤痕或未兑现的承诺，不能在后集凭空恢复或消失。

## 5. Context 读取与修改传播

**Context 切片加载**（Remember 步的唯一执行协议）：

```text
当前任务 → 相关 Canon/Intent → 上集 Snapshot → 相关角色/资产
        → Graph 邻接 → 未兑现 Promise → 当前媒体
```

先从直接节点开始；当已有足够 Canon、State、人物动机、因果与制作限制来做决定时**停止扩展**；只有证据不足、因果跨越、人物行动无因、Promise 无法承接、资产状态不明或状态冲突时，才扩展到相邻依赖。不要将所有角色、所有资产、全文剧本或历史媒体塞入 Context。

**变更记录**：`变更 ID / 类型 / 旧→新 / 依据或事件 / Graph 影响 / 已刷新 / 待刷新`。只将受影响下游标为 `stale`：

| 变化源 | 至少重查 |
|---|---|
| Canon、世界规则、人物动机/关系、信息权限 | Snapshot、相关剧本/状态、镜头信息释放、声音、媒体 |
| 美学锚点 / 导演 INTENT 修正（DEC-H） | 所有已按旧锚点比对的媒体、Visual Bible、镜头色彩/质感/光态规格、SPEC/MEDIA QA 结论 |
| Character DNA、资产身份/锁（含配音参数）、环境状态 | 相关变体、关键帧、提示词、参考、TTS 参数、后续镜与媒体 |
| 场景行动/对白/画内文字/声音 | 分镜、关键帧、视频/TTS/字幕/音乐、剪辑 |
| 镜头边界/时长/构图/声音 | 关键帧、视频规格、参考、剪辑/续接 |
| prompt/模型/参考/参数 | 预览、未运行任务、相关媒体与后续续接 |
| 已生成媒体/剪辑观察 | 剪辑与 QA；必要时回到规格、分镜、剧本或 State |

**Presentation 页面**：`P-` ID、页面绑定与 stale 传播规则见 [Presentation 手册](presentation.md) §2；此处唯一宪法约束：页面不是新 Context，页面变化不传播到故事事实。

**变化执行**：`Change → Dependency Graph → Stale Scope → Recheck`（原则见 SKILL §07）。`stale` 代表重新判断范围，**不代表必须重生成**：先 `Re-read → Re-plan → Reuse → Edit → Regenerate`。只有缺陷破坏 Identity、Canon、State、核心动作、必要信息、情绪意图或交付可用性时才重拍/重生；可由剪辑、裁切、叠字、色声修整或局部编辑解决的不得重投。用户要求同步时才递归刷新至规格/QA，且永不自动重投有成本任务。

## 6. 真实媒体、生产边界与创意 QA

| 标记 | 含义 |
|---|---|
| `FACT` | 已确认 Canon/State/Intent 事实，可作为下游约束。 |
| `REF` | 真实可读、内容/用途/授权已检查的输入。 |
| `PLAN` | 用户将在外部界面挂载或提供的计划，不能冒充项目文件。 |
| `GEN` | 已写出的图像/视频/TTS/音乐规格，尚未生产。 |
| `MEDIA` | 已生成/导入的真实文件，可检查/剪辑，尚不等于质量通过。 |

每个 `REF/MEDIA` 写相对路径、来源/授权、用途（身份/造型/地理/构图/起始/结束/风格/声音）、控制/不得控制范围与实际检查内容。

**生产门执行细则**：每次外部生产按 **精确任务（模态、数量、规格、参考、参数、输出、成本/授权）→ 展示预览 → 创作者本次明确确认 → 执行 → 检查真实媒体 → 更新 Memory** 展开（门的宪法表述与确认失效规则见 SKILL §05-6）。中断任务先收集/检查已提交结果，不盲目重投。

**批次与升级（判断版）**：按场景批次生成、批次审查（3–5 镜/批），每批过 MEDIA QA 再投下一批。批内出现系统性缺陷（同一脸/服装/光态多镜同错）= **共同原因缺陷**：先修共同原因（IDENTITY 块/定妆参考图/参数/状态表），重验 1 镜通过再继续，不逐镜硬磕。同一镜 MEDIA QA 连续失败 2–3 次 = **规格错了**：停止重投，回 Direct 改规格（记 `DEC-H`）或改镜头职责；规格未变的重投是浪费调用。

**生产追踪**（`剧集/EP###.md` 内，跨会话断点）：

```text
| 任务 (ID) | 模态 | 批次 | 状态 | QA 结论 | 备注/缺陷位置 |
```

状态沿用 FACT/REF/PLAN/GEN/MEDIA；每镜/每对白/每音乐一行；会话结束必更新追踪并写明“下次恢复点”；恢复中断时先读追踪再决定下一任务。

**QA 三层**（顺序、结论词汇与 `PROVISIONAL` 规则见 SKILL §05-7）：

- `SPEC QA`：故事/人物、Canon/State/Graph 一致性、分镜与生成规格完备性、信息权限与观众期待。
- `MEDIA QA`：身份（DNA）一致性、状态一致性、高画质基线（见导演判断手册 §3）、授权与技术可用性。
- `CUT QA`：连续观看的剪辑、节奏、色/声接缝、字幕/响度、情绪回报与交付体验。

每个问题提供：位置（ID/时点）→ 事实/可见证据 → 观众或制作影响 → 最小修复 → 责任层 → 保留项。没有实际观看/聆听真实媒体时，`MEDIA QA` 与 `CUT QA` 必须为 `PROVISIONAL`。

**美学锚点**：契约期创作者认可的 3–6 张 REF 剧照，记入 Visual Bible 并声明锚定维度（见判断手册 §3）；MEDIA QA 第一项 = 与锚点比对（调色/质感/光方向是否接近锚点？）。无锚点时，SPEC QA 声明“无锚点”并在首集验收时补齐，不得按通过处理。

**各模态典型失效模式**（MEDIA QA 问“这个模态具体会怎么失效”，逐项核对并记录项与结论）：

- **图像**：IDENTITY 块/定妆参考图一致 · 高画质基线 7 项 · State 一致（变体/伤痕/持物）· 画内文字 · 美学锚点
- **视频**：首帧 = 已验收关键帧 · 主事件唯一 · 运动无跳变/穿模 · 口型（含对白时）· 物件持久 · 光影连续 · 时长闭合
- **TTS**：Voice LOCK（音色 ID/参数）· 专名发音 · 韵律与表演意图 · 呼吸/房间声匹配 · 无文本朗读感（VO/OS 分开）
- **音乐**：动机锁 · 入/出点 · 动态不盖对白 · 无未授权素材

**QA 记录与升级**：三层结论与证据化问题写入 `剧集/EP###.md` 的 QA 节；`PROVISIONAL` → `APPROVE`/`APPROVE_WITH_NOTES` 的升级路径：完成真实观看/聆听 → 分模态清单逐项勾选 → 重写结论并附证据位置。

**最小 Continuity Lint**（导演判断前的安全网，不替代导演判断）：ID 是否唯一可追溯？是否继承上集 Snapshot？道具是否有位置/持有者转移链？时间/光态是否连续或有例外？角色是否按当前知识行动？每镜是否有职责？时长是否闭合？未检查媒体是否标 `PROVISIONAL`？
